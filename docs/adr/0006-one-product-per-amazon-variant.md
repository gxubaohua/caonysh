# 每个 Amazon listing 变体各建一个 Product（推翻 ADR-0005）

状态：已接受（supersedes ADR-0005）

Caonysh Amazon 店铺的目录在 Amazon 侧呈两层结构：9 个独立 listing，其中皱纸（11 个颜色变体）与花架（36 PCS / 60 PCS 两个型号变体）各自挂在一个 listing 下，7 个桌布则一色一 listing。本决策将全部 20 个变体（7 桌布 + 11 皱纸 + 2 花架）各建为一个 Product：图片、标题、五点描述、价格逐字取自该变体自己的 Amazon 详情页（仅修正源数据中的 "Tablet Cover" 拼写错误为 "Table Cover"，其余逐字保留）。

理由：

- 买家按变体搜索与询价——颜色和型号是采购决策的一部分，每个变体值得一张自己的卡片、一个自己的详情页与自己的价格（皱纸 11 色虽然当前同价 $8.99，花架 36/60 PCS 价差 $11.99/$19.99，虹光桌布 $7.89 与单色 $8.49 也不同）。
- 与 GLOSSARY 的 Product 定义（"可被询价的最小销售单元"）天然一致；ADR-0005 的合并在"整个配色族是一次询价的单元"语义下成立，但放弃了按变体的独立落地页与询盘上下文。
- ADR-0005 当初合并的主要顾虑（3 商品的目录里 7 个仅颜色不同的页面显得重复）在"逐字保真源数据"的诉求面前不再成立：不同变体的图片本就零重合，五点共属同一 listing 属实，但标题、价格、主图各不相同。

代价：目录从 3 条膨胀到 20 条，同一 listing 的变体详情页内容高度相似（五点相同），存在 SEO 重复内容风险；Product Config 的维护粒度变细（改一次五点要动多条）。若未来回到合并口径，恢复 ADR-0005 的做法即可（颜色写回 Specs 的 `Colors` 行）。

连带决策：价格按变体实价填 `price: { min }`（两态 Price Strategy 不变，ADR-0004）；五点描述新增 `bullets: string[]` 字段承载（可选，缺省不渲染列表），不进 Specs——五点是结构化列表，Specs 是自由键值参数表，语义不同； Featured 按每 listing 一条代表变体标记（Home 页展示 9 条）。

# 七个桌布配色合并为单一 Product

Caonysh 的真实产品线(源自其 Amazon 店铺)包含 7 个一次性亮面桌布 listing(虹光、蓝、粉、金、黑银、粉银、紫),除颜色外尺寸、材质、包装完全相同。Product Config 中将它们建模为**一个** Product(slug `foil-glitter-tablecloths`),颜色写入 Specs 的 `Colors` 行,价格取单色零售价 $8.49(维护者后定的口径,放弃了最初按虹光 $7.98–单色 $8.49 区间呈现的方案),图片取 4 个代表配色的 Amazon 主图。

理由:询盘站是询盘漏斗,不是零售目录——买家关心的是"54×108 亮面桌布能不能做、起订多少、有什么色",一个页面完整回答;7 个仅颜色不同的详情页内容高度重复,会让小目录显得单薄。代价:放弃按配色独立 SEO 落地页与独立询盘统计;若未来需要按配色拆分,重建页面与测试的成本明确存在。

备选方案:每配色一个 Product(镜像 Amazon listing 结构)。被否,因为目录规模(3 商品)下重复内容占 70%,得不偿失;且 GLOSSARY 的 Product 定义("可被询价的最小销售单元")在合并语义下依然成立——整个配色族就是一次询价的单元。

**与 ADR-0004 的关系**:价格策略的两态模型(填 min/max 或不填)不变,本决策只是区间的又一个合法用例;不新增 schema 字段(无 variants/colors 字段),变体信息全部走自由键值的 Specs。
